# Engineering comparison — ArtCraft Launcher vs Challenger Hub Preview 8

Source reviewed: [storytold/craft-launcher](https://github.com/storytold/craft-launcher) at commit `9419d89`. This is code-oriented review, not a change in product architecture or an unauthorized fork.

| Concern | ArtCraft approach | Challenger before | Decision / implementation in Preview 8 |
|---|---|---|---|
| Installation ownership | [InstallSource enum](https://github.com/storytold/craft-launcher/blob/9419d89/crates/core/src/status.rs) distinguishes managed, MSI, macOS app, Flatpak, package manager, AppImage, binary | Craft scan detected version and executable location but not who installed it | **Implemented guarded assessment** in `managed-install-status.js`. Detected executable does NOT imply Challenger ownership. Reports `ownerVerified:false` and `mayAutoReplace:false`; no unattended takeover |
| Truthful release status | [Typed AppStatus](https://github.com/storytold/craft-launcher/blob/9419d89/crates/core/src/status.rs) differentiates checking, no release, unavailable, installed with unknown release, upgrade available and up-to-date | UI often collapsed ambiguous statuses to “Installed”, “Source only” or “Approved adapter” | **Implemented** state mapping in server and `project-quality-ui.js`, including failure/cached release states without inventing “up-to-date” |
| OS snapshot | [Detection module](https://github.com/storytold/craft-launcher/blob/9419d89/crates/native/src/detect.rs) collects system package state once and also recognizes installations not created by the launcher | Program Files/macOS bundle detection repeated per app and does not inspect publisher/package provenance comprehensively | **Future:** shared read-only cross-platform OS snapshot; no newly granted install/remove rights until proven |
| Self-updater | [Post-exit helper](https://github.com/storytold/craft-launcher/blob/9419d89/crates/native/src/self_update.rs) deals with Windows locked executables, restart, persisted marker against update loops, and different package types | Hub Preview 7 checks official GitHub test releases and navigates to download but cannot safely swap running EXE | **Future gated:** signed, explicitly user-approved update staging/verification/restart, rollback and anti-loop marker. Do not transplant an unreviewed updater today |
| Release source / fallback | [Backend](https://github.com/storytold/craft-launcher/blob/9419d89/crates/native/src/backend.rs) has structured release cache / source origin and bounded API behavior | Challenger Preview 6 already introduced gh-authenticated refresh, bounded scanning, ETag revalidation and independent source signal freshness | **Keep working infrastructure.** Do not duplicate the ArtCraft-specific release feed for 152 unrelated projects |
| Product imagery | Bundled real licensed Craft app icons and original screenshots from [craft-launcher-assets](https://github.com/storytold/craft-launcher-assets/tree/v1) | Only 10 bundled vetted icons and 3 screenshots for entire registry; independent resolver read README only | **Implemented:** 13 Craft icons + 47 original screenshots bundled with attribution; independent tree+README scan of 152 and pinned SHA256 on-demand media for 36 projects (16 icons / 46 images) |
| Windows shell | Minimal native Rust egui launcher instead of a heavyweight web app | Native .NET WebView2 wrapper, but Preview 7 forced maximized and required scroll on resize | **Kept WebView2 architecture:** normal bounded 1100×760 launch, usable height-aware content, no shell rewrite, tested browser and real Win32 window geometry |
| Source-specific installer adapters | Upstream owns narrowly vetted Craft package matching, checksum and update rules | Challenger already has its own adapter/checksum gates | **No replacement now.** Official launcher is linked from Craft dossiers, but no imaginary CLI/API contract or automatic delegation |

**Safety rules:** Source metadata, release observations and UI images are NOT an approval to install, update, remove or self-update software. No Codex/API service, local daemon, scheduled task or persistent service is needed for this comparison. Never use brand-demo icons from other companies as the project’s official icon.

**Next engineering milestone:** Prove installation ownership via OS-level publisher/package identifiers and local manifest, then verify 1 safe third-party install/update/rollback in a test environment with explicit approval. Consider extending the upstream source-priority model before implementing an automatic Hub updater. No Production merge implied.
